# Shishli Finance — معالجة مخاطر الجاهزية

تاريخ التقرير: 2 نوفمبر 2026. هذا التقرير هو النتيجة الأحدث بعد معالجة ملاحظات `FINAL_REVIEW.md`.

**اجتازت الإصلاحات الاختبارات المحلية، بما فيها MySQL والتزامن والمتصفح مع API حقيقية. لا يمثل ذلك إجازة نشر على VPS أو إعلان جاهزية إنتاج نهائية؛ بقي تحقق DNS وHTTPS والتهيئة المرحلية وخطة الاستعادة قبل الموافقة الصريحة على النشر.**

لم يُنفذ SSH أو نشر أو Migration أو Seeder على الإنتاج. شُغّل Docker Desktop محليًا كما طُلب؛ استأنف تلقائيًا حاويات سابقة، ولم أستخدمها للاختبار أو أطبق عليها أوامر قاعدة بيانات. أُنشئ مشروعا اختبار منفصلان، دون ملفات بيئة أو أحجام أو شبكات المطعم، ثم أُوقفت حاوياتهما فقط بعد التحقق.

## تصميم المصادقة والعزل

- الدخول المالي الجديد: `POST /api/v1/finance/login`، بنفس تحقق كلمة المرور والمستخدم النشط وSanctum الحاليين، مع اشتراط `finance.access`.
- الخروج المالي: `POST /api/v1/finance/logout`. يحذف التوكن المستخدم فقط، ويظل توكن مالي آخر صالحًا حتى انتهائه أو إبطاله؛ اختُبر ذلك.
- `/api/v1/login` و`/api/v1/logout` الحاليان باقيا العقد والسلوك للتطبيقات القائمة. استُخدم خيار مالي صريح في `LoginUserAction` بدل تغيير السياسة العامة أو `sanctum.expiration`.
- أُضيف حاجز عام محدود الغرض: يرفض المسارات المالية على مضيف غير موثوق، ويرفض استخدام التوكن المسمى `finance` خارج مساحة المالية. لا يغيّر انتهاء أو قدرات التوكنات العادية.
- المضيف المعتمد يأتي من `FINANCE_HOST`، وافتراضيًا `finance.shishlifresh.com`. الاستثناءات `localhost` و`127.0.0.1` و`::1` متاحة في local/testing فقط؛ اختبار production يمنعها.
- يقرأ الحاجز ترويسة Host الفعلية بعد التحقق من شكلها، ولا يتخذ قرار السماح من ترويسات المضيف المعاد توجيهها. Nginx المالي يرفض المضيف المختلف، ويثبت المضيف المرسل إلى PHP-FPM.
- CORS ليس أساس العزل؛ الصلاحيات والفرع ونوع التوكن والمضيف مفروضة على الخادم. لا تمت إضافة cookie/CSRF flow أو تغيير قائمة Sanctum stateful domains.
- توكنات المالية القديمة العامة لا تُقبل للوصول المالي بعد هذا الإصلاح؛ يتطلب المستخدم تسجيل دخول مالي جديد. لا يوجد حذف شامل لتوكنات المستخدمين الآخرين.

## المصادر والتصنيفات والترقية

الترحيل الإضافي:

`back-end/database/migrations/2026_11_02_174242_add_stable_codes_to_finance_settings.php`

يضيف code فريدًا وغير nullable بعد تعبئة الصفوف القديمة. أكواد المصادر الافتراضية: `network`, `cash`, `transfer`, `keeta`, `jahez`, `hungerstation`. للتصنيفات أكواد ثابتة مستقلة أيضًا. العناصر المخصصة تحصل على code يولده الخادم، ولا يستطيع نموذج الإعدادات تغييره.

يحافظ الترحيل على UUID والأسماء والمبالغ والعلاقات. عند ترقية صف أعيدت تسميته عبر النظام القديم، يستخدم سجل التدقيق لربط الهوية القديمة بالكود دون إعادة الاسم الافتراضي؛ اختُبر ذلك على المحركين. لا يفترض أرقام IDs. إذا كان سجل التدقيق ملتبسًا بين أكثر من صف، يتوقف بدل اختيار هوية عشوائية. تعديل قديم مباشر لقاعدة البيانات دون اسم افتراضي أو أثر تدقيق لا يمكن استنتاج هويته تلقائيًا؛ يحتاج مراجعة وربطًا صريحًا عند الترقية، لا تخمينًا.

للإصدار الأول على قاعدة المطعم، يلزم الترحيل المالي الأصلي **ثم** ترحيل الأكواد قبل Seeder. لا يكفي تنفيذ الترحيل الأصلي وحده. هذه ملاحظة لخطة النشر المستقبلية، ولم يُنفذ أي منهما على الإنتاج.

## الترويسات

حماية استجابات API المالية تشمل:

- `Cache-Control: private, no-store`
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: SAMEORIGIN`
- `Referrer-Policy: strict-origin-when-cross-origin`

تُطبق على النجاح وأخطاء المصادقة والصلاحيات والخادم، مع إبقاء رسائل الخطأ العامة الآمنة. تكرار الترويسات في مواضع Nginx التي تعرّف `add_header` يحافظ على سياسة الأب بدل إسقاطها بالوراثة. الأصول الثابتة غير الحساسة تحتفظ بسياسة التخزين المؤقت الخاصة بها. قالب وكيل HTTPS يضيف HSTS للنطاق المالي فقط دون `includeSubDomains`، ولا يغير نطاق المطعم.

## بيانات المتصفح وGit

التصنيف بالقراءة فقط كشف **3 حقول أسماء و3 حقول هواتف**، وهي بيانات اتصال شخصية محتملة. لم تُطبع القيم، ولم تُنسخ إلى الأدلة. جداول كلمات المرور والكوكيز والبطاقات المفحوصة كانت فارغة كما في المراجعة السابقة.

أُزيل **2003 ملف جلسة متصفح** من فهرس Git، ضمن هذه المسارات فقط:

- `front-end/.delivery-ux-check/live/profile/`
- `front-end/.delivery-ux-check/profile/`
- `Şişli/.preview/chrome-check/`
- `Şişli/.preview/chrome/`

استُخدم `git rm --cached` بعد التحقق من بقاء المسارات داخل مساحة المشروع. الملفات باقية على القرص. قواعد التجاهل أُضيفت إلى `.gitignore` وجُهزت في الفهرس مع إزالة التتبع. لم يُستخدم reset أو clean أو إعادة كتابة تاريخ أو commit. لم تُستبدل التغييرات السابقة في المشروع.

هذا ينظف التتبع الحالي، **ولا يمحو النسخ الموجودة في تاريخ Git**. لم يُنفذ تنظيف تاريخي دون موافقة، ولا تعني النتيجة أن كل أشكال البيانات الحساسة في التاريخ قد مُسحت. اختبار `finance.repository.test.mjs` يتحقق من عدم عودة ملفات الجلسات أو ملفات البيئة الفعلية إلى التتبع؛ يتخطى فحص Git فقط إذا كانت الشيفرة حزمة مصدر لا تحتوي `.git`.

### ما كشفته الجولة الأولى وصُحح

لم تُخفَ إخفاقات الجولة الأولى: خطآن كانا في اختبارات التقوية نفسها، أحدهما مقارنة أجزاء الثانية بعد تخزين التاريخ بدقة الثانية، والآخر إرسال توكن مالي عند اختبار الدخول الإداري العام؛ صُحح تجهيز الاختبار. الاختبار المالي عبر Host استُخدم معه URI كامل لتجسيد مضيف الطلب في Symfony بصورة صحيحة.

أما إخفاق إنشاء اليوم بالتزامن على MySQL فكان خللًا فعليًا: القراءة غير المقفلة داخل Repeatable Read ظلت ترى لقطة سابقة بعد انتظار قفل الفرع، ثم اصطدمت بقيد التكرار وأعادت 500. أُصلح بفحص قراءة مقفلة، وطُبق الفحص نفسه على فواتير الموردين وأضيف اختبار تزامن لها. الجولة النهائية اجتازت الحالات الأربع.

## BACKEND → FRONTEND COVERAGE

الخلفية أصبحت توفر دخولًا وخروجًا ماليين محددي النطاق والانتهاء. الواجهة انتقلت إليهما باستخدام طبقة Axios الحالية، وتظل حالة 401 تُنهي الجلسة المالية الحالية. لا يوجد تدفق cookies جديد أو تغيير في واجهات العملاء والإدارة. الأكواد ثابتة ويديرها الخادم فقط ولا تتحول إلى حقول قابلة للتحرير في الواجهة. الترويسات وعزل المضيف وأقفال المعاملات داخلية، وتختبر من API وNginx بدل الاعتماد على إخفاء عناصر الواجهة.

## إعادة التحقق محليًا

من `back-end`:

```powershell
php vendor/bin/phpunit -c phpunit.finance.xml
```

ومن جذر المستودع، لقاعدة MySQL الجديدة المعزولة فقط:

```powershell
docker compose -f docker/compose.finance-test.yaml up --build --abort-on-container-exit --exit-code-from finance-tests
```

دورة المتصفح الفعلية تحتاج بيئة تشغيل اختبارية جديدة؛ لا تعِد تشغيلها على بيانات دورة سابقة:

```powershell
docker compose -f docker/compose.finance-runtime-test.yaml up -d --build
```

ثم من `front-end`: `npm run test:finance:live`. الاختبار مقيد بمنفذي loopback المخصصين ويتحقق من هوية الحساب والفرع الاختباريين وخلو الإيرادات قبل الكتابة، ولا يقبل عنوان إنتاج. لإيقاف الحاويات المملوكة لهذه التجربة فقط، استخدم `stop` مع ملف Compose نفسه. لا تستخدم Compose المطعم لهذه الاختبارات.

## ما بقي قبل إجازة الإنتاج
