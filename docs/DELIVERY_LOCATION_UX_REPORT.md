# شيشلي — تقرير تحسين تجربة موقع التوصيل

التاريخ: 14 أكتوبر 2026. النسخة التي جرى التحقق منها: http://127.0.0.1:8088.

## تحديث البحث الحالي

تظهر اقتراحات Photon تلقائيًا بعد ثلاثة أحرف واستقرار الكتابة 600ms؛ Nominatim تبقى لوصف الموقع. البحث مقيد ببلد المطعم (SA افتراضيًا)، وبمدينة الفرع، وصندوق جغرافي يمتد 30 كم في كل اتجاه حوله، مع استبعاد نتائج البلد أو المدينة المختلفة. لفرع المصيف تُستخدم مدينة تبوك وموقع الفرع، وتُستبعد نتائج العراق والرياض. هذا نطاق بحث تقريبي، وليس حدود المدينة الإدارية أو منطقة التوصيل؛ قواعد التغطية والرسوم في Laravel لم تتغير. أُثبت نجاح استعلام حقيقي عن تبوك مع قيد السعودية والنطاق الجغرافي.

هذا التحديث يحل محل وصف البحث الصريح في تقرير المرحلة الأولى أدناه.

## النتيجة

نُفذت تجربة اختيار موقع بدبوس ثابت، وتحريك الخريطة، ونافذة سفلية للهاتف، وبحث صريح، والتحقق التلقائي من التغطية والرسوم. احتُفظ بـLeaflet وOpenStreetMap وNominatim. لم تُضف خدمة مدفوعة أو مفاتيح سرية للواجهة.

تم إنشاء طلب توصيل نقدي حقيقي عبر الواجهة وLaravel/MySQL برقم **SH-0005**، برسوم توصيل **5.00 ريالات** محسوبة من الخادم. أُلغي طلب الاختبار مباشرة عبر API الإلغاء المعتادة، وبقي سجله بحالة `cancelled`. لم يُسجّل تحصيل نقدي ولم تُحذف بيانات الاختبار من قاعدة البيانات.

## المشاكل التي كشفها التحليل

| المشكلة | السبب والنتيجة | المعالجة |
|---|---|---|
| صعوبة ضبط المكان على الهاتف | الاعتماد على دبوس يُسحب واستهدافه بدقة، مع زر إضافي لاختيار منتصف الخريطة | دبوس ثابت وتحريك الخريطة تحته؛ يبدأ التحقق بعد استقرارها |
| رسالة GPS عامة | رفض الإذن وانتهاء المهلة وتعذر الجهاز لها الرسالة نفسها | رسائل مستقلة، ومهلة للانتظار، ومسار بديل للخريطة |
| تعطل GPS على بعض الروابط | API الموقع تحتاج سياقًا آمنًا وإذنًا؛ HTTP على عنوان الشبكة المحلية لا يعادل localhost | فحص السياق الآمن وتوضيح الحاجة لـHTTPS؛ تأكد عمل 127.0.0.1 كسياق آمن |
| دقة موقع منخفضة | إحداثيات الجهاز قد تكون تقريبية، خصوصًا داخل المباني | عرض الدقة بالمتر عندما تتجاوز 100 متر، وإتاحة مراجعة موضع المبنى |
| بطء إكمال العنوان | حقول عديدة ظاهرة، والتحقق يدوي، ووصف الموقع منفصل عن قرار الاختيار | إكمال الوصف تلقائيًا، وإخفاء تفاصيل الوصف داخل قسم قابل للتعديل عند اكتماله، وإبقاء تفاصيل الوصول اختيارية |
| غياب البحث | اختيار الدبوس كان الخيار الجغرافي الأساسي | بحث عن حي/شارع/معلم عند الضغط على «بحث»، ونتائج قابلة للاختيار على الهاتف |
| التحقق يمنع تعديل الموقع | quote كان يعطل نموذج Checkout ويرتبط بحالة تعديل السلة | تحقق قابل للإلغاء دون تعطيل الخريطة؛ يبقى إرسال الطلب محميًا أثناء التحقق |
| احتمال عودة quote قديمة | إبطال نتيجة السلة لم يكن يرفع إصدار الطلب دائمًا، ولم تُلغَ طلبات HTTP | AbortController وإصدارات للعنوان والسلة والفرع والجلسة؛ منع نشر النتائج القديمة |
| حفظ عنوان قبل اكتمال الموقع | حالة جلب الموقع/الوصف لم تصل إلى زر حفظ العناوين | تمرير busy ومنع الحفظ أثناء الحركة أو جلب الموقع/الوصف |
| ضبط مدينة بعنوان ثابت | بعض العناوين افترضت تبوك من اسم الفرع | استخدام المدينة الفعلية المسجلة للفرع |
| حدود Nominatim غير مشتركة | الانتظار في المتصفح لا يحد مجموع مستخدمي المشروع | بوابة Nginx واحدة للبحث والوصف، بحد مشترك وذاكرة مؤقتة |

هذه نتائج مراجعة الكود والاختبارات، وليست إثباتًا أن كل فشل GPS سابق سببه واحد. لم تتبين ضرورة تغيير مزود tiles: تم تحميل الخرائط الحالية فعليًا والتقاط موقع الفرع بنجاح، دون إجراء تقييم شامل لتغطية جميع المدن.

## تجربة المستخدم الجديدة

1. يختار العميل «استخدام موقعي الحالي»، أو «اختيار الموقع على الخريطة»، أو الإدخال اليدوي عندما تسمح التغطية بذلك.
2. تظهر نافذة سفلية على الهاتف، ونافذة حوار على الشاشة الكبيرة. تبقى أزرار الخريطة والبحث واضحة.
3. يبقى الدبوس في المركز، ويتحرك محتوى الخريطة. يمكن العودة إلى آخر موقع GPS جُلب بنجاح.
4. يُلغى وصف الموقع والتحقق السابق بمجرد بدء الحركة. بعد انتهاء الحركة يُجلب وصف العنوان مع debounce قدره 800ms، ثم يُجدول quote بعد استقرار البيانات بـ900ms.
5. تظهر المدينة والحي والشارع المستخرجة. يستطيع العميل تعديلها، ولا يُطلب منه إعادة كتابتها إذا كانت متوفرة. عند نقص المدينة أو الحي أو فشل الخدمة يظهر قسم إكمالهما.
6. تُعرض التغطية والرسوم في الجزء السفلي الثابت من النافذة، بجانب زر واحد واضح: «استخدام هذا العنوان».
7. تفاصيل المبنى والطابق والشقة والمعلم والتعليمات اختيارية. معلومات المبنى لا تُخمن من مزود وصف الموقع.
8. اختيار عنوان محفوظ أو تعديله يعيد التحقق باستخدام UUID، مع الحفاظ على الإضافة والتعديل والحذف والعنوان الافتراضي.

وصف reverse geocoding تقريبي؛ لا يُستخدم دليلًا نهائيًا على صحة موضع العميل. معيار منطقة المسافة يبقى الإحداثيات وفق قواعد Laravel الحالية.

## الخرائط والمزود والحدود

- Leaflet يعرض الخريطة والدبوس. OpenStreetMap هو مصدر tiles الحالي، مع إسناد المصدر الظاهر.
- `locationProvider.js` يفصل واجهة `reverse` و`search`، ويتيح استبدالها عبر `setLocationProvider` أو ضبط نقاط الاتصال العامة.
- الخدمة الافتراضية تمر عبر `/map-geocoding/reverse` و`/map-geocoding/search` على نفس أصل الموقع. يمكن تبديل مزود متوافق في إعداد Nginx دون تغيير Vue.
- البحث البعيد يحدث فقط بعد الضغط على «بحث» أو Enter. الكتابة لا ترسل طلبات Autocomplete إلى Nominatim.
- Nginx يحدد مجموع طلبات البحث والوصف بـ1 طلب/ثانية لهذه الحاوية، مع تأخير انتظار محدود، و429 عند تجاوز الطابور. النتائج الناجحة تُخزن يومًا، مع قفل للطلبات المكررة.
- تُرسل طلبات المزود باتصال HTTPS موثّق الشهادة ومعرّف تطبيق واضح، دون تمرير cookies أو Authorization الخاصة بالعميل. المضيف والمساران محددان ولا يسمحان بتمرير مضيف arbitrary.
- Vite يمرر مسارات geocoding إلى nginx على 8088 في التطوير. يلزم تشغيل هذه البوابة، أو ضبط مزود بديل مناسب.

الحد الرسمي لـNominatim يشمل مجموع مستخدمي التطبيق، وتمنع الخدمة العامة Autocomplete. البوابة تحقق الحد المشترك في نشر Docker الحالي ذي nginx واحدة. إذا توسع النشر إلى عدة بوابات مستقلة، يجب توحيد الحد بينها أو استخدام مزود مناسب. [سياسة Nominatim](https://operations.osmfoundation.org/policies/nominatim/).

التكلفة الإضافية الحالية: **لا اشتراك ولا مزود مدفوع جديد**؛ يستخدم التخزين المؤقت مساحة محدودة داخل حاوية nginx، دون volume جديد. الخدمات العامة لا تقدم ضمان توفر؛ يجب مراعاة سياسة tiles عند النشر والإبقاء على الإسناد والتخزين المعتاد دون تنزيل جماعي. [سياسة OpenStreetMap tiles](https://operations.osmfoundation.org/policies/tiles/).

GPS يحتاج سياقًا آمنًا وإذن المستخدم، وقد تمنعه Permissions Policy. localhost و127.0.0.1 يُعاملان كسياق آمن، بينما رابط IP الشبكة المحلية عبر HTTP لا يضمن ذلك. لم تُنشأ شهادة HTTPS محلية أو يُختبر نطاق HTTPS فعلي في هذه المهمة. [MDN: Geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)، [MDN: Secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts).

## سلامة نظام التوصيل

لم تُعدل ملفات حساب الرسوم أو أولويات المناطق أو معادلة GeoService أو صلاحيات الإدارة والمندوبين في هذه المهمة.

الواجهة تطلب quote من السلة الفعلية دون إرسال رسوم أو إجمالي موثوق من العميل. تُحفظ الإحداثيات والنصوص في حقولها الحالية؛ Laravel يعيد التحقق من صلاحيتها والتغطية والتوفر والأسعار عند إنشاء الطلب. لم تُضف طريقة لإثبات الموقع الفعلي ضد تزييف GPS؛ التحقق الجغرافي الحالي يعتمد على النقطة المرسلة بعد التحقق منها.

الإدخال اليدوي يحافظ على قوائم أحياء الفرع. عند إلزام الإحداثيات لا يظهر مسار تجاوز نصي. الخريطة الثابتة اختيارية في المكون المشترك؛ لوحة الإدارة تحتفظ بالدبوس القابل للسحب ودائرة التغطية الحالية.

## Docker

لم تتغير Compose أو الشبكات أو volumes. تعديل إعداد nginx ضروري لتطبيق حد Nominatim على مجموع المستخدمين، والتحقق من TLS وإخفاء بيانات العميل عن المزود. بُنيت وأُعيدت خدمة `nginx` فقط باستخدام `--no-deps`؛ لم تُشغل migrations أو seeders ولم يُعدل مجلد `Şişli` المرجعي. حاويات e2e الموجودة لم تُحذف.

## BACKEND → FRONTEND COVERAGE

- الميزات الموجودة في الخادم: quote للسلة، أحياء/مسافات التغطية، شرط الإحداثيات، العناوين المحفوظة، حفظ لقطة العنوان، والتحقق النهائي عند Checkout.

- بقيت حسابات الأسعار والأولويات والمسافات والصلاحيات في Laravel؛ لم تُنقل للواجهة لأنها قواعد تشغيل وأمان داخلية.
