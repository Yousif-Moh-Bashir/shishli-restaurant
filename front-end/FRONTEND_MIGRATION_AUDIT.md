# Settings conversion and frontend migration audit

Date: 2026-10-04. Scope: Settings only; backend and legacy project were read only. No API integration or automatic audit fixes.

1. **Legacy files inspected:** `Şişli/dashboard/settings.html`, `assets/css/dashboard.css`, `assets/js/store.js`, `assets/js/dashboard.js`, `assets/js/icons.js`. Referenced assets: `assets/images/logo.png`, Tajawal Google Fonts (400–900), inline SVG icons. Existing Vue CSS, logo, fonts and icon component were reused; **no CSS or assets were copied or changed in this task**.
2. **Backend files inspected:** `routes/api.php`; `Services/RestaurantSettingDefinition.php`, `RestaurantSettingsService.php`, `BranchAvailabilityService.php`, `BranchScheduleService.php`, `BusinessHoursOverlapValidator.php`; `Actions/Settings/UpdateRestaurantSettingsAction.php`, `Actions/Branches/ReplaceBusinessHoursAction.php`, `ManageBranchClosureAction.php`; admin `RestaurantSettingsController.php`, `BranchBusinessHoursController.php`, `BranchClosureController.php`, `DeliveryZoneController.php`; public `PublicConfigurationController.php`, `BranchStatusController.php`; admin requests `UpdateSettingsRequest.php`, `StoreBranchRequest.php`, `ReplaceBusinessHoursRequest.php`, `StoreBranchClosureRequest.php`, `StoreDeliveryZoneRequest.php`; resources `RestaurantSettingResource.php`, `PublicConfigurationResource.php`, `BranchResource.php`, `BranchBusinessHoursResource.php`, `BranchAvailabilityResource.php`; models `RestaurantSetting.php`, `Branch.php`, `BranchBusinessHour.php`, `BranchClosure.php`, `DeliveryZone.php`; enums `DayOfWeek.php`, `PaymentMethod.php`; config `business.php`, `payments.php`, `outbound_notifications.php` and mail/services environment references. Paths under `app/` unless noted. No `.env` values were read or exported.
3. **New files:** `src/views/admin/SettingsView.vue`, `src/composables/useAdminSettingsPreview.js`, this audit document.
4. **Modified files:** `src/router/index.js`, `src/components/admin/AdminSidebar.vue`, `src/data/adminDashboard.js`. Build regenerated `dist/`. Temporary browser scripts/profiles/screenshots are removed after verification.
5. **Route:** `/admin/settings`, named `admin.settings`, child of existing `AdminLayout`. Existing Sidebar/Header are reused; all seven navigation links use Vue Router, with correct active state.
6. **Actual sections:** one panel, “بيانات المطعم”; six required inputs: name, phone, address, map URL, opening time, closing time. No tabs, logo upload, branch selector, reset/cancel button, switches, payment or notification sections exist in the original. None were added.
7. **General settings:** backend registry has groups `general`, `contact`, `branding`, `orders`, `pickup`, `delivery`. Actual keys include `restaurant.name/name_en/phone/whatsapp/email/currency/timezone/country/city`, `branding.logo_path/primary_color`, ordering limits, guest/scheduled checkout controls and maintenance. Group `contact` does **not** mean keys use a `contact.*` prefix. PATCH payload uses literal dotted keys, e.g. `{settings: {'restaurant.name': '…'}}`. Registry types/validation/public visibility are authoritative, not arbitrary DB metadata.
8. **Branch data:** separate `branches` domain: UUID, name, slug, phone, WhatsApp, city, district, address, latitude/longitude, `is_active`, `accepts_orders`, `supports_pickup`, `supports_delivery`, sort order. `BranchResource.id` contains the UUID. Legacy map link has no direct branch/settings field; no coordinates or branch identity are inferred. The six-field form is a presentation draft, never an API “God Settings Object”.
9. **Business hours:** `branch_business_hours`, one row per period: `{day_of_week, opens_at, closes_at}`; ISO Monday=1…Sunday=7, `H:i`. PUT `{hours:[…]}` replaces the complete week; omitted days are closed. GET returns `{timezone, days:[{day_of_week, day_name, periods:[{opens_at, closes_at}]}]}`. Overnight periods belong to opening day; backend rejects equal endpoints and circular-week overlaps. Frontend validates format only, and permits closing earlier than opening. Current legacy UI has just one time pair, not a weekly editor. Closures use separate `branch_closures` with UTC `starts_at`, `ends_at`, reason and `is_active`; holidays can be represented as closures. No separate special-hours override contract was found in the inspected scheduling service.
10. **Ordering authority:** actual service is `BranchAvailabilityService`, not an assumed `BranchOperationService`. Precedence: `orders.maintenance_mode`, `orders.enabled`, active/not-deleted branch, `branch.accepts_orders`, temporary closure, weekly hours, global pickup/delivery switches and branch support. Inactive, closed and temporarily not accepting orders are distinct. Vue does not calculate a definitive open/ordering state.
11. **Pickup/delivery:** registry keys `pickup.enabled/minimum_amount/default_preparation_minutes`, `delivery.enabled/default_preparation_minutes/require_coordinates`; global `orders.minimum_amount`. Branch support flags are separate. Fees, minimum order, free-delivery threshold, estimated times, districts/radius and priority are in `delivery_zones`; Settings does not calculate a quote or manage zones. Backend has delivery quote endpoints.
12. **Payment settings:** no payment keys in the settings registry and no safe payment-settings CRUD endpoint found. `PaymentMethod` is `cash` or `card`; mada/Apple Pay are not separate enum values here. `config/payments.php` selects `PAYMENT_DEFAULT_PROVIDER`, currently has an empty provider registry, and sets webhook limits/timestamp tolerance. Admin payment operations are not provider configuration. No payment toggle or claim of a working provider was added.
13. **Notifications:** `config/outbound_notifications.php` defines SMS/WhatsApp/email channel enablement/provider selection (all disabled by default), per-event mappings, WhatsApp templates, queue, retries and backoff. Admin API lists notifications/attempts and retries delivery; it is not channel/provider-settings CRUD. No notification toggles exist in legacy Settings.
14. **Sensitive data:** provider credentials, payment/webhook secrets, private keys, WhatsApp tokens, SMS keys and SMTP passwords remain server/environment concerns. None was copied to Vue or `VITE_*`; no frontend `.env` files or `VITE_*` variables were found in the inspected project. Public restaurant contact information is not a provider credential.
15. **Actual admin endpoints**, prefix `/api/v1/admin`:

    | Method | Path | Purpose |
    | --- | --- | --- |
    | GET | `/settings` | Registry-backed settings |
    | GET | `/settings/groups` | Settings grouped by registry group |
    | PATCH | `/settings` | Update validated literal dotted keys |
    | GET | `/settings/audit` | Change history |
    | GET, POST | `/branches` | List/create branches |
    | GET, PUT, PATCH, DELETE | `/branches/{branch}` | Branch details/update/delete |
    | GET, PUT | `/branches/{branch}/business-hours` | Read/replace weekly schedule |
    | GET, POST | `/branches/{branch}/closures` | List/create closures |
    | PATCH, DELETE | `/branches/{branch}/closures/{closure}` | Update/delete closure |
    | GET, POST | `/branches/{branch}/delivery-zones` | List/create zones |
    | GET, PATCH, DELETE | `/branches/{branch}/delivery-zones/{deliveryZone}` | Zone details/update/delete |
    | GET | `/notifications` | List notifications |
    | GET | `/notifications/{notification}` | Notification details |
    | GET | `/notifications/{notification}/attempts` | Delivery attempts |
    | POST | `/notifications/{notification}/retry` | Retry delivery |

    Branch operational flags are updated through branch PUT/PATCH, not a fabricated operations-settings endpoint. No payment/provider or notification/channel settings endpoint was found.

16. **Actual public endpoints**, prefix `/api/v1`: GET `/settings/public`, `/branches`, `/branches/{branch}`, `/branches/{branch}/status`, `/branches/{branch}/business-hours`. The registry allowlist controls public settings; internal `orders.guest_tracking_token_days` is omitted. Maintenance message is included only while maintenance is enabled. No admin settings collection is exposed by the public endpoint.
17. **Permissions:** `settings.view`, `settings.update`, `settings.audit.view`; `branches.view/create/update/delete`; `branches.hours.view/update`; `branches.closures.view/create/update/delete`; `delivery_zones.view/create/update/delete`; `notifications.view/retry`. Admin routes also require `auth:sanctum`, `EnsureAdminAccess` and activity recording. Vue has no fabricated authenticated admin or permission grant; current admin is an open presentation preview.
18. **Cache:** typed settings snapshot uses `Cache::rememberForever('restaurant.settings.v1')`, guarded by `restaurant.settings.write` lock (15-second lease, up to 5-second wait). Updates use a DB transaction, row locks and change logs, then forget cache and register an after-commit forget. Public settings and branch status responses use `Cache-Control: private, no-store`. Inspected branch schedule/status services evaluate current rows/settings without a separate long-lived schedule cache; schedule and closure writes lock the branch transactionally.
19. **Settings demo behavior:** defaults reuse `config/restaurant.js` for public name/phone/address/map, plus original `11:00`/`02:00` time pair. Existing legacy preview loader may read prior browser settings, but never writes. Form has reactive fields, frozen original snapshot, computed dirty state, reset helper, field-message arrays, general error and submitting state. Laravel 422 messages can be mapped per domain; that adapter is not an API implementation. Successful validation explicitly says values were **not saved/sent**. Draft never updates shared public config, backend or localStorage; it resets when leaving/reopening the page. No extra reset button was added.
20. **Visual result:** screenshot PNG hashes were identical for all 7 admin pages at 1440×1100, 768×1024 and 390×844 (21 comparisons), including Settings. RTL, original classes/layout and native time inputs remain. Initial/default view matched; validation messages and honest preview notification are intentional behavior changes. Site routes passed 36 responsive render/isolation/no-overflow checks. This does not claim pixel comparison for empty legacy site files or a complete transaction regression of all pre-existing forms.
21. **Build:** `npm run build` passed, 91 modules; Vite 8.3.2. Existing CSS bundle remained unchanged. No build errors.
22. **Browser diagnostics:** no Vue warnings, runtime/console errors, HTTP 404 or other HTTP failures during the checks; zero `/api/` requests. Settings tests passed for invalid map URL, blank name, invalid phone, overnight hours, honest preview message, dirty/reset behavior, mapped Laravel errors, no storage mutation, SPA layout cleanup and unchanged public configuration.
